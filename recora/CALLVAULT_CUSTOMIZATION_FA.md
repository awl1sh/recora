# تغییرات بسته تحویلی CallVault

- سورس اصلی پروژه حفظ شده و شناسه برنامه در فایل‌های متنی و مسیرهای سورس به `ir.callvault.app` تغییر کرده است.
- تنظیم Gradle برای انتشار اصلاح شده: build نوع release غیرقابل دیباگ است و دیگر از `debug.keystore` یا `androiddebugkey` استفاده نمی‌کند.
- برای ساخت release باید متغیرهای محیطی `RELEASE_STORE_FILE`، `RELEASE_STORE_PASSWORD`، `RELEASE_KEY_ALIAS` و `RELEASE_KEY_PASSWORD` با اطلاعات keystore واقعی مالک تنظیم شوند. این اطلاعات عمداً داخل ZIP قرار داده نشده‌اند.
- کلاینت خواندنی API در `cloud/CloudContentClient.kt` اضافه شده است. پس از نصب پنل، مقدار `REPLACE_WITH_PANEL_API_KEY` را با کلید API خواندنی جایگزین کنید. کلید داخل APK قابل استخراج است و فقط باید دسترسی read-only داشته باشد.
- کلاینت داده‌های پیام و تبلیغ را در حافظه محلی cache می‌کند و در خطای شبکه از cache استفاده می‌کند. برای اتصال آن به رویداد بازگشت اپ به foreground، تابع `CloudContentClient.sync(context)` باید از lifecycle صفحه اصلی فراخوانی شود؛ در این بسته کد client فراهم شده، اما UI نمایش popup/banner و اتصال به منوی ناوبری هنوز نیازمند ادغام و تست روی دستگاه است.
- نسخه PHP پنل از API بدون Push استفاده می‌کند؛ در نتیجه اپ در زمان اجرای فعال یا بازگشت به foreground داده را دریافت می‌کند، اما اعلان فوری در حالت بسته بودن اپ فراهم نیست.
- تغییر package name باعث می‌شود نصب قبلی با شناسه `com.baba.callvault` به‌عنوان همان اپ به‌روزرسانی نشود؛ نصب جداگانه خواهد بود.
- امکانات ضبط تماس به نسخه اندروید، سازنده گوشی، مجوزها، شیوه نصب/راه‌اندازی ADB یا Shizuku و قوانین محل کاربر وابسته‌اند. هیچ تضمین ضبط همه تماس‌ها روی همه گوشی‌ها داده نمی‌شود.
- پیش از انتشار، تست کامل Gradle، اجرای instrumentation tests، بررسی سیاست‌های Google Play درباره Call Log/Phone permissions و ضبط تماس، و بررسی مجوز GPLv3 و NOTICE الزامی است.
